When a dispatch forbids touching production code, prove kills with a scratch config under test/ (vitest.config.js must be importable): mergeConfig(base, { plugins: [{ enforce: 'pre', transform(code, id) }], test: { setupFiles: [scratch setup] } }) where transform applies process.env.MUT = JSON {file, pairs:[[from,to]]} to vite-loaded modules, and the setup patches fs.readFileSync (default export object) then calls module.syncBuiltinESMExports() so named `import { readFileSync }` users (popup-script-loader) and new Function / fs readers also see the mutant. A node .cjs driver in %TEMP% loops mutants, runs `npx vitest run --config <scratch> <spec> --reporter=json --outputFile=...`, prints failed test titles. Handle CRLF files by converting '\n' in from/to. 2026-11-08: 64 auto-copy/popup mutants proven this way in ~6 min. Recycle the scratch files after.

**Why:** in-place mutation of production files is forbidden by some dispatches, and git checkout restore would destroy uncommitted work anyway ([[pitfall_mutation_restore_git_checkout]]).

**How to apply:** for load-time branches (typeof module/window/require, optional chaining on globals, auto-start calls) evaluate the source with `new Function('globalThis','window','module','require', src)` and a container object as globalThis holding the real fresh dependencies. Pitfall: a destructuring default `({ window = {} })` turns an explicit `window: undefined` back into {} - use `{ window: {}, ...bindings }` spread instead. Every `utils/storage-manager.keys.js` DEFAULTS literal survives Stryker because the only default assertions read the copy vitest.setup.js preloaded (static coverage, ignoreStatic hybrid planning skips them); kill by evaluating keys.js inside the test body. See [[stryker-scoped-run]], [[iife-load-side-effect-sandbox]].

Concurrent agents (2026-11-08): another test-engineer used the same scratch names (test/scratch-mut.setup.js, scratch-mut.shared.js, scratch-mut.config.js) and overwrote my setup mid-run; give scratch files and the env var an agent-unique prefix (e.g. te2kill.*, TE2MUT) and never recycle files you did not create. Strict-mode artifact: popup scripts load through evalPopupScript, a direct eval inside an ES module, so they run strict in tests although Chrome loads them sloppy; a mutant that assigns a property on a string primitive (`|| []` -> `|| ["Stryker was here"]` then `r.checked = ...`) throws TypeError only in tests. Such a kill is valid under Stryker but production-equivalent; say so in the report. Radio-group exclusivity makes guard variants of `if (r.checked !== (r.value === val)) r.checked = (r.value === val)` DOM-equivalent in any list order, while a revert loop `radio.checked = (radio.value === 'off')` -> `true` is killed only by moving the off option first in the mounted markup.

Pitfall (2026-11-08): a backslash regex like /\/g written through a Bash heredoc reached the scratch file mangled and esbuild failed to load the config, so every mutant reported SURVIVED with no report. Use String.fromCharCode(92) for the separator, and always run a no-op baseline row first and treat "no report" as a broken harness.

Shortcut for vm-booted wiring specs (2026-11-08, service-worker.clipboard-wiring): copy background/service-worker.js to test/<prefix>.sw-mutant.js and a no-op test/<prefix>.sw-baseline.js, then copy the spec to test/unit/<prefix>.{baseline,mutant}.spec.js with the boot line pointed at the copy; importScripts still resolves against BACKGROUND_DIR, so no transform plugin or fs patch is needed. Also: the SW harness (test/helpers/service-worker-harness.js) stubs every route global by hand, so each new DSS*Routes.install() in the SW breaks 9 sweep specs until a stub is added.

Stryker attribution for new Function sandboxes (2026-11-08, checked in instrumenter dist/src/util/syntax-helpers.js:15): the preamble uses `globalThis` only when `globalThis.Math === Math`, otherwise the real global. A container built with Object.create(globalThis) therefore still reaches the real `__stryker__` namespace (activeMutant and per-test coverage) through its prototype. A vm context (load-classic-script.js) does not, so mutants would never activate there. Driver tip: build the rows file from several short heredocs, because one heredoc of about 60 long lines failed with "unexpected EOF".
