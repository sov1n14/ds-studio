# Overlapping Async Writes: Older Resolves Last

**Cause**: v4.35.3 — in an existing chat with no stored binding, picking preset B while the chat→preset bind to the service worker failed rolled the dropdown label back to the placeholder, but the injected prefix kept B's content. The overlay's optimistic `updatePromptPrefixFromBinding()` awaited `getSettings()`; the rollback's call on the unbound chat set the prefix synchronously, so the older optimistic call resolved last and overwrote it — the stale async result won. The failed-bind consistency spec covered only a chat already bound to preset A, where the rollback also awaits and finishes last, so the unbound branch that writes synchronously never lost the race in a test. Some failure modes (NO_RECEIVER with retry, timeout) delay the rollback enough to avoid the race, so covering "a failure mode" was not enough, and the `sendMessage` double lacked the resolve-`undefined` shape that triggered it live (see [boundary-doubles-must-copy.md](boundary-doubles-must-copy.md)).

**Solution**: a generation counter makes the latest `updatePromptPrefixFromBinding()` call win. `test/unit/content-script.overlay-failed-bind-consistency.spec.js` runs every failure mode against an unbound chat and asserts the displayed label and the injected prefix agree. On pre-fix code, 4 failure modes on an unbound chat (rejection / port closed, resolves `undefined`, synchronous throw, `{ok:false}`) failed with "overlay shows no preset, so B's content must not be injected: expected '…GLOBAL-INSTRUCTION… PREFIX-B…' not to contain 'PREFIX-B'"; NO_RECEIVER with retry and timeout passed because their delayed rollback naturally avoids the race.

**Prevention**: State written by overlapping async calls MUST have a scenario test in which the older call resolves last, once per branch that writes synchronously and once per branch that writes after an await. Run the scenario for every failure mode of the trust boundary, since each mode shifts timing differently. Assert that the consumers of the state agree with each other (displayed label vs injected prefix), not each in isolation.

**Check**: For each async writer of shared state, list its callers and mark which write before and which after an await; confirm a test orders the older call to resolve last for each pair. Then remove the latest-wins guard and confirm at least one of those tests goes red.
