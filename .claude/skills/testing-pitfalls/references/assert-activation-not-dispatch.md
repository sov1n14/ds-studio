# Host-Page Controls: Assert Activation, Not Dispatch

**Cause**: through v4.35.3, fixed in v4.35.4 — auto-continue and auto-retry did nothing on the live page. `content/auto-retry.js` clicked DeepSeek's continue/retry buttons with `button.click()`. DeepSeek's React `onClick` acts only when `e.nativeEvent.isTrusted === true && e.nativeEvent instanceof Event`, so every untrusted synthetic click (`.click()`, a dispatched pointer/mouse sequence, focus + click) was silently ignored. `test/helpers/auto-click-harness.js` mirrored the live markup exactly, and the tests asserted success as "a `click` listener on the button fired N times". The fixture copied the markup but not the page's handler behavior, and "event fired" stood in for "button activated", so the suite stayed green while the feature was dead.

**Solution**: the MAIN-world bridge `content/react-click-bridge.main.js` calls the element's `__reactProps$*` `onClick` with a synthetic event whose `nativeEvent` satisfies the guard; `content/auto-retry.js` requests it with a `dss:react-click` event and the bridge falls back to a native click on elements without React props. `guardButton()` in `test/helpers/auto-click-harness.js` gives a fixture button the live `__reactProps$*` expando with an `onClick` that activates only under the isTrusted guard, and returns an activation spy. `test/unit/auto-click.react-guard.scenario.spec.js` asserts activation per round, plus a fixture self-check that an untrusted `.click()` activates nothing. On pre-fix code, 6 of 9 tests failed, including "continue activations after round 1 (guarded onClick must accept the event): expected "spy" to be called 1 times, but got 0 times" and the same for retry; the fixture self-checks passed.

**Prevention**: When a test asserts that the extension clicked or triggered a host-page control, the test double MUST model the page's real acceptance logic as observed live (trusted-event guards, React handler props, disabled states), not only its markup. The assertion MUST target the page-level outcome — activation or the resulting state change — never the fact that an event was dispatched. The fixture MUST carry a self-check that an untrusted `.click()` does NOT activate the double, so a harness that accepts any event cannot pass.

**Check**: Before trusting a click/trigger test, confirm on the live page (DevTools) how the control's handler decides to act, and confirm the double reproduces that decision. Confirm the fixture self-check fails if the guard is removed from the double. Then revert the production click path to a plain `button.click()` and confirm the activation assertions go red.
