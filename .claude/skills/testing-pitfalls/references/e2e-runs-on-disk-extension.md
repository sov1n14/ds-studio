# E2E Must Run the Extension on Disk

**Cause**: the E2E suite drives the unpacked extension inside a persistent Chrome profile. That profile kept running a cached background service worker script from an older version while the repo on disk held a newer one: the worker behaved like the pre-fix code, yet reloading the extension from inside the worker (`chrome.runtime.reload()`) made it run the disk code with storage unchanged. The worker-scoped fixture took whichever extension service worker was registered after launch and never checked that it ran the code on disk, so every spec could pass or fail against stale code while appearing to test the current change.

**Solution**: `test/e2e/helpers/extension.js` `reloadExtension(context)` waits for a new extension worker (registered before the trigger), triggers `chrome.runtime.reload()` from the current worker, retires the old worker handle so later lookups cannot return it, and returns the new worker. The `profileContext` fixture in `test/e2e/fixtures.js` calls it once per Playwright worker right after launch, before any DeepSeek page opens, then fails with both values when the worker's `chrome.runtime.getManifest().version` differs from the version in `manifest.json` on disk; `test/e2e/smoke.e2e.js` asserts the same equality as a test. The original stale state could not be recreated, so the guard was proven red by pointing the expected version at a wrong value: the fixture failed with "Extension version mismatch: service worker reports 4.39.13, manifest.json on disk is 0.0.0-red-probe", and the smoke test failed with Expected "0.0.0-red-probe", Received "4.39.13".

**Prevention**: An E2E fixture that loads an unpacked extension into a persistent profile MUST reload the extension once before the first page opens and MUST assert that the running extension reports the version on disk before any test uses it. A fixture MUST NOT accept whatever service worker happens to be registered, and a helper that caches or looks up worker handles MUST exclude the handle retired by a reload.

**Check**: Before trusting an E2E run, confirm the fixture log or a smoke test shows a new worker after the reload and a running version equal to the disk `manifest.json`; then point the expected version at a wrong value once and confirm the fixture fails with both values named.
