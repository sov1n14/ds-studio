# Tab-Targeted Messages: Fake Every Tab and Honor Query Filters

**Cause**: through v4.39.16, `sendActivePresetToContentScript()` in `popup/popup.js` called `DSSTabControl.broadcastActivePreset`, which sends `ACTIVE_PRESET_CHANGED` to every tab returned by `chrome.tabs.query({url})`. Each content script wrote the message's group into its own pending group, so picking a group in the popup, and even opening the popup, changed the group of every open DeepSeek new-conversation tab, and opening the popup over a tab with no group sent `''`, which the other tabs took as an explicit blank over their pinned default. The `broadcastActivePreset` tests in `test/unit/tab-control.spec.js` asserted only "delivered to every tab", against a fixed `chrome.tabs.query` mock whose list ignored the query filters (`active`, `currentWindow`), so "the tab under the popup" and "any other tab" were never distinguishable. The content-script message-handler tests drove a single instance, so no test ever read a second tab's state after a popup action.

**Solution**: the popup calls the new `DSSTabControl.sendActivePresetToActiveTab`, which queries the active DeepSeek tab of the current window and sends to it alone. `test/helpers/fake-chrome-tabs.js` is a `chrome.tabs` double whose `query` filters the tab table by `active`, `currentWindow`, `lastFocusedWindow`, `windowId` and `url`, and records an unknown query key in `fakeErrors` instead of ignoring it. `test/unit/tab-control.spec.js` (6 new tests) uses it, and `test/unit/popup-pick-tab-scope.scenario.spec.js` (4 tests, with `test/helpers/popup-send-path-harness.js`) runs the real popup send path over tab A and a real content-script instance as tab B, then asserts B's shown group and injected prefix are unchanged after a popup pick and after a popup open over a tab with no group. Observed red on 4.39.16 code across the three scoped files: 10 failed, 15 passed; green after the fix: 75 passed.

**Prevention**: A test of any message that targets "the tab under the popup", "the current tab" or one tab among several MUST use a tab double with at least one non-target tab (a background tab of the same window and an active tab of another window), whose `query` honors every filter the code passes, and MUST fail loudly on a filter the double does not know, so a fixed list that ignores filters cannot stand in for it. The test MUST assert the non-target tab's observable state (its shown value, its next injected prefix) is unchanged after the action, in addition to what the target tab received; it MUST run the real receiver for the non-target tab, because a count of delivered messages cannot show what the receiver does with one. Include the trigger that sends an empty value (a popup opened over a tab with no group), because an empty value can overwrite a default.

**Check**: Before trusting a tab-targeted test, change the sender to broadcast to every tab (restore the pre-fix call) and confirm a test fails on the non-target tab's state; a pass means the double ignores the query filters or the non-target tab has no real receiver. Grep the test's `chrome.tabs.query` double for the filter keys the code under test passes and confirm each one filters.
