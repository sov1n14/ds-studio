# Host Contract Names: Assert Against the Live Page

**Cause**: from the initial commit 6c74a4c through v4.36.5, `NATIVE_BTN_INLINE_STYLE` in `content/go-top.js:26` (at HEAD 0872dfe) gave the solo-fallback go-top button the custom property `--dsl-button-hover-color`, but DeepSeek's stylesheet `main.312b2a151e.css` reads only `--dsl-button-color-hover`, and the wrong name occurs there zero times. The solo button therefore fell back to `outlinedNeutral`'s translucent grey (`rgba(38, 49, 72, 0.06)` in the light theme) on hover, while the live native floating button sets `--dsl-button-color-hover: var(--dsw-alias-button-floating-hover)` inline and gets `rgb(241, 243, 245)`. `test/unit/go-top.button.spec.js:54` and `:96` (at HEAD 0872dfe) asserted `toContain('--dsl-button-hover-color')` against the extension's own string, a value transcribed from the implementation, so the typo passed every run.

**Solution**: `content/go-top.js:26` writes `--dsl-button-color-hover`, the name DeepSeek reads, and `test/unit/go-top.button.spec.js` derives the expected property name from the native button's inline style in `test/fixtures/ds-snapshots/conv2-finished-message-list.html` instead of from the code under test. On the pre-fix `content/go-top.js`, `npx vitest run unit/go-top.button.spec.js` gave `Tests  2 failed | 26 passed (28)`, with the failures "template path: declares the hover custom property the live native floating button sets, with the floating-hover value" (`expected undefined to be 'var(--dsw-alias-button-floating-hover)'`) and "template path: declares no hover custom property that the live native floating button does not set" (`expected [ '--dsl-button-hover-color' ] to deeply equal []`). After the fix, the same command gives `Tests  28 passed (28)`.

**Prevention**: A CSS custom property, class, or attribute name that the extension writes for host-page CSS to read MUST be asserted against the name in a captured live snapshot under `test/fixtures/ds-snapshots/` or in the host stylesheet, never against the string in the extension code. A test MUST NOT take an expected name from the module under test. A disagreement between the code's name and the snapshot's name is a defect in the code.

**Check**: For each such name, run `timeout 120 grep -c -F '<name>'` on the captured snapshot and confirm a count of at least 1. Confirm the name also appears in the stylesheet rule that reads it, using the live stylesheet in DevTools or a saved copy. Then change the name in the code to a misspelled variant and confirm the test goes red.
