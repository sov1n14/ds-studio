# Close and Unload Paths: Assert What Is Persisted at the Instant of Close

**Cause**: through v4.39.6, fixed in v4.39.7 — pressing `Esc` in the prompt group editor window (`popup/editor/editor.js`, shipped in v4.15.0) called `window.close()` at once. The save is an async multi-step storage chain, and the `pagehide` / `visibilitychange` backstops are fire-and-forget, so they cannot finish during unload; the typed name and content were lost. `test/unit/editor.spec.js` missed it three ways: it asserted source strings (`toContain('window.close()')`, `debouncedSave()`) that pinned the buggy wiring, the `DOMContentLoaded` closure that holds the handlers was never executed, and every save assertion waited for the save to settle, so nothing checked the persisted state at the moment the window closed.

**Solution**: `popup/editor/editor.autosave.js` adds a controller whose `flush()` the `Esc` handler awaits (bounded by `ESC_SAVE_WAIT_MS`) before calling `window.close()`. `test/unit/editor.escape-save.scenario.spec.js` drives the real editor through `test/helpers/editor-window-harness.js` (real `editor.js`, real `StorageManager`, an in-memory `chrome.storage`; only `chrome.storage` and `window.close` are doubles), and the `window.close` spy snapshots storage at the call. On the 4.39.6 code 2 of the 6 tests failed (dirty `Esc`: `expected 'poc original' to be 'poc renamed'`; duplicate name: `expected 1 to be +0`) and 4 passed; all 6 pass now. The 4 source-text cases in `test/unit/editor.spec.js` were deleted.

**Prevention**: A test for any path that closes, unloads, or navigates away from a page that holds unsaved state (`Esc`, a close button, `pagehide`, a route change) MUST execute the real handler and assert what is persisted at the instant the close is requested, by snapshotting storage inside the `window.close` (or equivalent) spy. A fire-and-forget async flush inside `pagehide` or `visibilitychange` is not a save guarantee and MUST NOT be accepted as the reason a close path is lossless. A test MUST NOT assert source text of the file under test.

**Check**: Before trusting a close-path spec, confirm that the close spy reads storage at call time and that the expectation does not run after the save settles. Revert the wait in the handler and confirm the spec goes red with the stored value still the original. Search the spec for `readFileSync` of the production file and for `toContain` on its text, and replace each hit with a behavior assertion.
