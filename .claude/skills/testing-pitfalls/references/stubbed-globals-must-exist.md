# Cross-Script Globals: Load the Real Scripts

**Cause**: in v4.39.18 every incomplete Markdown export (cancelled, stalled, scroll-interrupted) downloaded nothing and showed no warning toast. `content/content-script.export.js:185` called `showHarvestToastIncomplete(...)` as a bare global, but no content script defines that name: `content/harvest.toast.js` publishes it only inside the `globalThis.__DS_Harvest_toast` bundle, and `content/harvest.js:24-27` binds only `showHarvestToastScrolling`, `showHarvestToastCapturing` and `hideHarvestToast` from it. The ReferenceError skipped `downloadMarkdown`, and the `.catch` in `content/content-script.js:231-233` swallowed it. `test/unit/content-script.export.spec.js:312` and `test/unit/export-collapsed-thinking.scenario.spec.js:92` called `vi.stubGlobal('showHarvestToastIncomplete', ...)`, so the specs themselves supplied the global the browser lacks, and every incomplete-export test passed. Vitest also imports each script as its own module, so no import-based spec can observe what one classic script can or cannot see of another.

**Solution**: `test/unit/export-incomplete-cancel.scenario.spec.js` runs the export-path scripts as classic scripts in one fresh `vm` context that acts as the isolated-world global, in `manifest.json` `content_scripts` order, stubs only Blob, `URL.createObjectURL`, `alert` and the download navigation, presses the real progress toast's cancel button, and asserts the downloaded file, its last line `> ⚠️ Export may be incomplete (2 messages captured): the export was cancelled.` and a visible `.dss-harvest-toast--incomplete`. On the 4.39.18 code, `npx vitest run unit/export-incomplete-cancel.scenario.spec.js` gave `Tests  1 failed | 1 passed (2)` with "the cancelled export downloaded no Markdown file; the export rejected with ReferenceError: showHarvestToastIncomplete is not defined: expected [] to have a length of 1 but got +0". The bare-global stubs are gone: the collapsed-thinking spec never reaches the toast, and `content-script.export.spec.js` now imports the real `content/harvest.toast.js` and asserts the toast on the page, so its seven incomplete-export tests also fail on the 4.39.18 code with "showHarvestToastIncomplete is not defined". After the fix resolves the toast from `globalThis.__DS_Harvest_toast` at call time, the scenario spec and `content-script.export.spec.js` pass, and a cancelled export still downloads its file when the toast bundle is absent.

**Prevention**: A test MUST NOT stub, define or assign a global that no production script defines in the same world; supply a collaborator by loading its real script or by replacing the member of the global object that production publishes, such as `globalThis.__DS_Harvest_toast`. A behavior that crosses content scripts through globals MUST have at least one scenario test that runs the real scripts in `manifest.json` order in one shared `vm` context, the way `test/unit/service-worker.*-wiring.spec.js` runs the service worker. An assertion on a collaborator's effect reads the page (the toast element, the downloaded file), not a spy standing in for the collaborator.

**Check**: For every `vi.stubGlobal(<name>, ...)` or `globalThis.<name> =` in a test, run `timeout 120 grep -rnw "<name>" content utils background` and confirm one hit defines the name in the world the code under test runs in, as a global property or a top-level declaration (destructuring included); a member of a bundle object or a name declared inside an IIFE does not count. Then run the scenario test with the stub removed and confirm it fails with the ReferenceError the browser would raise whenever production does not define the name.
