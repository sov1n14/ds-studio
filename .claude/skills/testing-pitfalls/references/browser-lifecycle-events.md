# Browser Lifecycle Events: Fire Only What the Browser Fires

**Cause**: through v4.39.20 — pressing the browser toolbar reload button on a temporary conversation deleted it, against the user ruling "refreshing should not clear temporary conversations". The content script told a reload from a leave inside the page: a `navigate` event with `navigationType: 'reload'` or an F5 / Ctrl+R keydown armed a suppression, and `handleBeforeUnload` in `content/temporary-chat-delete.handlers.js` otherwise sent a `keepalive` delete. The toolbar reload fires neither a `navigate` event nor a keydown, so the page saw only `beforeunload`, the same event as a tab close, and deleted. The suite missed it because `test/unit/temporary-chat-delete.late-toggle.scenario.spec.js` modelled the "reload button" case as a faked `navigate` reload event followed by `beforeunload`: the test supplied the one suppression signal the real button never produces, so the case stayed green.

**Solution**: the page stops deciding. `beforeunload` sends `DSS_TEMP_CHAT.DSS_MSG_TAB_UNLOADING` with the tracked uuid and keeps its `sessionStorage` tracking; `background/unload-grace.js` waits a 10 s grace period and deletes only when no `DSS_HEARTBEAT` for the uuid arrived and no `chat.deepseek.com` tab still shows it, so the reloaded page claims the conversation. `test/unit/temporary-chat-delete.unload-message.spec.js` drives the real listeners with `beforeunload` alone, then loads a second page on the same `sessionStorage` and expects its heartbeat; `test/unit/service-worker.unload-grace.scenario.spec.js` boots the real service worker through `test/helpers/unload-grace-harness.js` and drives the grace decision through runtime messages only; the late-toggle reload-button case now dispatches `beforeunload` alone. On the v4.39.20 code 32 of the 689 tests in the temporary-chat and service-worker specs failed and 657 passed, among them the late-toggle reload-button case ("a reload or a tab switch must keep temporary conversation U: expected [ { channel: 'fetch', …(2) } ] to deeply equal []") and the unload-message reload case ("the reload must not delete S from page A: expected [ { channel: 'fetch', …(1) } ] to deeply equal []"). Post-fix result: on the 4.39.21 code the temporary-chat, service-worker and unload-grace specs pass, 718 of 718 (`npx vitest run unit/temporary-chat unit/temp-chat unit/content-script.chat-delete unit/service-worker unit/unload-grace` from `test/`), while with the five changed production files reverted to their v4.39.20 versions the same run fails 48 and passes 670; the scoped Stryker gate passes with 175 of 189 mutants Killed and 14 equivalent mutants ignored by `Stryker disable` comments.

**Prevention**: A test that simulates a browser action (the toolbar reload button, back or forward, a tab or window close, an address-bar navigation, a key shortcut) MUST dispatch only the events the browser fires for that action, as observed on the live browser, and MUST NOT add an event the real action lacks (a `navigate` with `navigationType: 'reload'`, a keydown). When two user actions produce the same event sequence in the page, the test MUST include each action with that identical sequence and assert the outcome the requirement sets for each; when the outcomes differ, the decision cannot live in the page, and the test MUST drive it where a distinguishing signal exists (here a later heartbeat or an open tab, seen by the service worker).

**Check**: For every simulated browser action in a spec, list the events it dispatches and confirm each one against a live capture of that action (an E2E run or a page with logging listeners). Search the spec for `new Event('navigate'` and `KeyboardEvent('keydown'` placed before `beforeunload`, and confirm each matches a real initiator (the F5 key, a script `location.reload()`), not a toolbar button. Confirm a case dispatches `beforeunload` alone for every action that produces only that event, tab close and toolbar reload both included.
