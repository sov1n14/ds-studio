# Host Re-Renders Overwrite Extension State

**Cause**: v4.35.5 and earlier, two live-page bugs on DeepSeek's sidebar wrapper `div.dc04ec1d` (natively collapsed: `dc04ec1d a02af2e6`, expanded: `dc04ec1d`). React rewrites the wrapper's whole `className` on every native toggle and, at narrow widths, keeps the rail `div.ca6d4be1` and its toggle button mounted, reusing the same node. (1) `content/sidebar-auto-hide.js` stored its collapsed state only as the class `ds-sidebar-auto-hide-collapsed` on the wrapper; `isCollapsed()` read that class, so after a React rewrite the module believed the sidebar was expanded, the sidebar observer took its overflow-only branch, and the sidebar stayed visibly open until a mouseleave, while hover `expand()` became a no-op. (2) `content/auto-open-sidebar.js` marked the clicked button with a per-node flag and observed only `childList`, so when DeepSeek re-collapsed the sidebar on the same node with a class-only change, nothing rescanned and the flag blocked any further click. The tests missed both: Group L in `test/unit/sidebar-auto-hide.spec.js` simulated a native toggle only by removing the rail node, never by rewriting the wrapper `className`, so a class stored on a host element was assumed to persist; the auto-open specs modelled every new collapse as a freshly mounted button, assuming DeepSeek remounts nodes on a state change.

**Solution**: red tests written before the fix. `test/unit/sidebar-auto-hide.spec.js` Group U sets `sidebarEl.className = 'dc04ec1d'` after `enable()` and asserts the module re-applies its collapse from its own intent with no mouse event (U1), does not re-collapse while the pointer is inside (U2), and still hover-expands after the class was wiped (U3). Observed red on pre-fix code: U1 "COLLAPSED_CLASS re-applied after the React rewrite: expected false to be true", U3 "expand() restored the original width: expected '60px' to be '250px'". `test/unit/auto-open-sidebar.spec.js` "collapsed episodes on a reused rail node" keeps the rail node mounted and flips only the wrapper className. Observed red: "second episode on the reused node (class-only change): expected "spy" to be called 2 times, but got 1 times", and the loop-breaker case "episode after a resize re-armed the breaker: expected "spy" to be called 2 times, but got 1 times".

**Prevention**: State the extension owns MUST NOT live only in a class or attribute on a host-page element; keep it in the extension's own JS state and treat the host attribute as an output that can vanish. A test of code that writes to a host element MUST model the host re-render that overwrites it (assign the whole `className`, as React does) and assert the extension restores or tolerates it. A test MUST NOT assume the host remounts nodes on a state change: model the live behaviour observed in DevTools, including the same node surviving the toggle with only an attribute flip, and assert that per-node flags still allow the next state transition.

**Check**: Before trusting a test of host-element state, confirm in DevTools what the host does to that element on each native state change (which attributes it rewrites, whether nodes are reused or remounted), and confirm the fixture reproduces exactly that. Then grep the code under test for state read back from a host-element class or attribute, and add a case that wipes that class mid-state and asserts the extension's behaviour.
