# Documented Behavior: Test the Input That Triggers It

**Cause**: through v4.39.10, fixed in v4.39.11 — with "show system time" on, resending or editing a message whose text already began with a `Current Time: ...` line made `injectPrefix()` in `content/prompt-injector.controller.js` prepend a second timestamp line. `docs/spec/04-features.md` and `docs/FEATURES.md` described the old line as replaced by the new one, but the code never did it. Every existing spec in `test/unit/prompt-injector.controller.spec.js` fed the injector plain user text, so no test ever exercised the one input the documented rule is about, and the suite stayed green while the documentation described behavior that did not exist.

**Cause** (regex boundaries): the first fix, a regex that strips a leading `Current Time:` line and the blank lines after it, passed the obvious cases, yet a first Stryker run left 8 surviving regex mutants. The first tests covered only the common shape, a time line followed by one blank line, so mutants of the line terminator, the blank-line repetition, the whitespace class, and the anchor behaved identically on those inputs.

**Solution**: `injectPrefix()` strips a leading `Current Time:` line plus following blank or whitespace-only lines before it prepends one fresh line. `test/unit/prompt-injector.system-time-dedupe.spec.js` feeds inputs that already start with a `Current Time:` line and asserts the exact textarea value; on the v4.39.10 code it was red because the sent text carried two `Current Time:` lines. The 8 surviving mutants were killed by exact-output cases: no blank line after the time line, several blank lines, whitespace-only lines, a time line that is not at the start of the text, and a time line with no trailing newline.

**Prevention**: Any behavior stated in `docs/`, a spec, or a code comment (deduplicate, skip, replace, never twice) MUST have a test whose input is the exact state that triggers it, not only the plain state around it. A test of a regex that strips, splits, or matches text MUST assert the full output string for each boundary: the empty or missing separator, one versus many repetitions, whitespace-only lines, a match away from the anchor, and no trailing newline. An assertion that a match "happened" does not count, because mutants of the pattern pass it.

**Check**: For each documented behavior the change touches, find the test whose input already contains the triggering state and confirm it exists; when none exists, write it and confirm it is red on the pre-fix code. For each regex under test, list its anchors, optional groups, and repetition operators, and confirm one exact-output case per element. Run Stryker on the file and confirm no regex mutant survives.
