# Documented Behavior: Test the Input That Triggers It

**Cause**: through v4.39.10, fixed in v4.39.11 — with "show system time" on, resending or editing a message whose text already began with a `Current Time: ...` line made `injectPrefix()` in `content/prompt-injector.controller.js` prepend a second timestamp line. `docs/spec/04-features.md` and `docs/FEATURES.md` described the old line as replaced by the new one, but the code never did it. Every existing spec in `test/unit/prompt-injector.controller.spec.js` fed the injector plain user text, so no test ever exercised the one input the documented rule is about, and the suite stayed green while the documentation described behavior that did not exist.

**Cause** (regex boundaries): the first fix, a regex that strips a leading `Current Time:` line and the blank lines after it, passed the obvious cases, yet a first Stryker run left 8 surviving regex mutants. The first tests covered only the common shape, a time line followed by one blank line, so mutants of the line terminator, the blank-line repetition, the whitespace class, and the anchor behaved identically on those inputs.

**Cause** (one-sided state): through v4.39.13, fixed in v4.39.14 — the migration push of `StorageManager.initialize()` (`utils/storage-manager.init.js`) is documented as pushing keys that are present locally but missing from sync, yet it read sync without the `dsPreset_<id>` keys, so every prompt group looked missing and was pushed on every popup open, and an older local copy overwrote a newer cloud copy. `test/unit/storage-manager.migration-push.spec.js` seeded an empty preset index and never put a prompt group in sync, so the preset loop never ran and the state "present in sync" that separates "missing" from "present" never existed in any test.

**Solution**: `injectPrefix()` strips a leading `Current Time:` line plus following blank or whitespace-only lines before it prepends one fresh line. `test/unit/prompt-injector.system-time-dedupe.spec.js` feeds inputs that already start with a `Current Time:` line and asserts the exact textarea value; on the v4.39.10 code it was red because the sent text carried two `Current Time:` lines. The 8 surviving mutants were killed by exact-output cases: no blank line after the time line, several blank lines, whitespace-only lines, a time line that is not at the start of the text, and a time line with no trailing newline.

**Solution** (one-sided state): the migration push reads the `dsPreset_<id>` keys of the local index from sync in the same single read and pushes a prompt group only when sync lacks it or `_shouldPushPreset()` picks the local copy. `test/unit/storage-manager.migration-push.presets.spec.js` (4 tests) seeds both areas: identical groups, a group missing in sync, a newer cloud group and a newer local group. It spies on `chrome.storage.sync.set` and asserts the exact `dsPreset_*` keys written plus the content left in sync, and a probe key missing from sync proves the push branch ran. Observed red on the v4.39.13 `utils/storage-manager.init.js` in a scratch copy: 3 of 4 tests failed (identical groups: received `["dsPreset_p1","dsPreset_p2"]` instead of `[]`; missing in sync: `dsPreset_p1` written as well as `dsPreset_p2`; newer cloud: `expected 'OLD-LOCAL' to be 'NEW-CLOUD'`) and the newer-local test passed.

**Prevention**: Any behavior stated in `docs/`, a spec, or a code comment (deduplicate, skip, replace, never twice) MUST have a test whose input is the exact state that triggers it, not only the plain state around it. A test of a regex that strips, splits, or matches text MUST assert the full output string for each boundary: the empty or missing separator, one versus many repetitions, whitespace-only lines, a match away from the anchor, and no trailing newline. An assertion that a match "happened" does not count, because mutants of the pattern pass it. A test of a rule that decides by comparing local state with cloud state (push only what is missing, never overwrite a newer copy) MUST seed both sides, with at least one item present on both sides, one present only locally, and one newer on each side, and MUST assert the exact keys written to the other side and the values it holds afterwards, because a fixture that seeds only the local side never reaches the "present" branch.

**Check**: For each documented behavior the change touches, find the test whose input already contains the triggering state and confirm it exists; when none exists, write it and confirm it is red on the pre-fix code. For each regex under test, list its anchors, optional groups, and repetition operators, and confirm one exact-output case per element. Run Stryker on the file and confirm no regex mutant survives. For a local-versus-cloud push or merge rule, list the collections the code reads on each side (index, per-item keys, settings keys) and confirm the fixture seeds each of them on both sides, including a non-empty item index; then run the test against the pre-fix code with a spy on the write call and confirm it lists the extra keys written.
