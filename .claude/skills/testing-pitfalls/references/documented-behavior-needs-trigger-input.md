# Documented Behavior: Test the Input That Triggers It

**Cause**: through v4.39.10, fixed in v4.39.11 — with "show system time" on, resending or editing a message whose text already began with a `Current Time: ...` line made `injectPrefix()` in `content/prompt-injector.controller.js` prepend a second timestamp line. `docs/spec/04-features.md` and `docs/FEATURES.md` described the old line as replaced by the new one, but the code never did it. Every existing spec in `test/unit/prompt-injector.controller.spec.js` fed the injector plain user text, so no test ever exercised the one input the documented rule is about, and the suite stayed green while the documentation described behavior that did not exist.

**Cause** (regex boundaries): the first fix, a regex that strips a leading `Current Time:` line and the blank lines after it, passed the obvious cases, yet a first Stryker run left 8 surviving regex mutants. The first tests covered only the common shape, a time line followed by one blank line, so mutants of the line terminator, the blank-line repetition, the whitespace class, and the anchor behaved identically on those inputs.

**Cause** (one-sided state): through v4.39.13, fixed in v4.39.14 — the migration push of `StorageManager.initialize()` (`utils/storage-manager.init.js`) is documented as pushing keys that are present locally but missing from sync, yet it read sync without the `dsPreset_<id>` keys, so every prompt group looked missing and was pushed on every popup open, and an older local copy overwrote a newer cloud copy. `test/unit/storage-manager.migration-push.spec.js` seeded an empty preset index and never put a prompt group in sync, so the preset loop never ran and the state "present in sync" that separates "missing" from "present" never existed in any test.

**Cause** (documented local-only key): through v4.39.14, fixed in v4.39.15 — `dsLocalAuth` (the sync-retry queue) and `dsOversizedKeys` are documented as local-only, yet the migration push of `StorageManager.initialize()` and the write-back of `resolveSyncConflict()` copied them to `chrome.storage.sync`, and the default fill of `initialize()` wrote `restored_messages: {}` to sync. After a sync-quota fallback the retry queue reached sync and a conflict merge could copy it into another device's queue. The existing `populateDefaults()` helper never seeded `dsLocalAuth` or `dsOversizedKeys` in the local area, so the push loop never saw them, and no test read the sync area for a documented local-only key after `initialize()` or `resolveSyncConflict()`.

**Cause** (documented import rule): through v4.39.15, fixed in v4.39.16 — the Import Restore Records handler in `popup/popup.backup-manager.js` rejected only a missing or non-object `restored_messages`, so an array was accepted and stored under the index keys `"0"`, `"1"`, and so on, and a file with more than 200 records was merged although 200 is the documented retention cap. No unit test drove the import handler at all, so no test fed it the two inputs the rule is about, an array value and a file above the cap, and the suite stayed green.

**Cause** (documented send rule): through v4.39.17, fixed in v4.39.18 — with "show system time" on, a composer holding only a stale `Current Time:` line was documented as left unsent and unchanged without an attachment, and as getting a fresh time line plus the group prefix with an attachment, yet DeepSeek sent the stale line unchanged in both cases. The Enter and send-button click handlers in `content/prompt-injector.controller.js` decided "has text" on the raw value, `injectPrefix()` stripped the line and returned false, and the handlers returned without blocking the event. The v4.39.11 tests (`test/unit/prompt-injector.system-time-dedupe.spec.js`, `test/unit/prompt-injector.system-time-dedupe.fresh-load.mutant-kill.spec.js`) called `injectPrefix()` directly on a detached textarea and asserted its return value and the textarea value, passing the sendable-without-text flag by hand as the second argument. They never fired the Enter or click event at the handlers and built no send button, so no test used the live send-button state, which is enabled whenever the textarea holds text, and none could show that the button state cannot signal an attachment.

**Solution**: `injectPrefix()` strips a leading `Current Time:` line plus following blank or whitespace-only lines before it prepends one fresh line. `test/unit/prompt-injector.system-time-dedupe.spec.js` feeds inputs that already start with a `Current Time:` line and asserts the exact textarea value; on the v4.39.10 code it was red because the sent text carried two `Current Time:` lines. The 8 surviving mutants were killed by exact-output cases: no blank line after the time line, several blank lines, whitespace-only lines, a time line that is not at the start of the text, and a time line with no trailing newline.

**Solution** (one-sided state): the migration push reads the `dsPreset_<id>` keys of the local index from sync in the same single read and pushes a prompt group only when sync lacks it or `_shouldPushPreset()` picks the local copy. `test/unit/storage-manager.migration-push.presets.spec.js` (4 tests) seeds both areas: identical groups, a group missing in sync, a newer cloud group and a newer local group. It spies on `chrome.storage.sync.set` and asserts the exact `dsPreset_*` keys written plus the content left in sync, and a probe key missing from sync proves the push branch ran. Observed red on the v4.39.13 `utils/storage-manager.init.js` in a scratch copy: 3 of 4 tests failed (identical groups: received `["dsPreset_p1","dsPreset_p2"]` instead of `[]`; missing in sync: `dsPreset_p1` written as well as `dsPreset_p2`; newer cloud: `expected 'OLD-LOCAL' to be 'NEW-CLOUD'`) and the newer-local test passed.

**Solution** (documented local-only key): the frozen list `SYNC_EXCLUDED_KEYS` (`utils/storage-manager.keys.js`) names the three keys; `initialize()` fills their defaults in local only and skips them in the migration push, and `resolveSyncConflict()` removes them from its write-back. `test/unit/storage-manager.local-only-sync-exclusion.spec.js` (5 tests) seeds the keys locally after a sync-quota fallback, runs the real `initialize()` and `resolveSyncConflict()`, and asserts the exact key set the sync area holds afterwards; a control test asserts that an ordinary setting sync lacks is still pushed. Observed red on the v4.39.14 code: 4 failed, 1 passed (the control).

**Solution** (documented import rule): the handler rejects an array through the existing format error and rejects a file with more than 200 records through the new `tooManyRestoredRecordsError`; only the record count of the file is checked, so a merged total above 200 is still accepted. `test/unit/popup.backup-manager.import-restored.spec.js` (11 tests, including zh-TW) drives the real handler with a file holding an array, a missing value, a non-object value, 201 records, exactly 200 records and a merge that pushes the local total above 200, and asserts the rendered error message and the exact `chrome.storage.local` content afterwards. The three added cases feed truthy non-object values (a non-empty string, a non-zero number and `true`) and assert the invalid-format message, because a Stryker mutant that replaced the object-type guard with `false` survived the eight original tests. Observed red on the v4.39.15 code for the eight original tests: 6 failed, 2 passed.

**Solution** (documented send rule): the new `hasComposerAttachment(textarea)` in `content/prompt-injector.send-button.js` detects an attachment card beside the main composer, and the handlers use it for a stale-line-only composer: with a card they send a fresh time line plus the group prefix, without one they suppress the event and leave the text. `test/unit/prompt-injector.stale-time-attachment-send.spec.js` fires the real Enter and click events at the real handlers over `makeLiveComposerBox` (`test/helpers/send-button-fixtures.js`, built from live DOM captures with an enabled button for any non-empty text) and asserts what the page sends, whether the event was prevented and the textarea value afterwards. Observed red on the v4.39.17 production code: 10 failed of 22 in that spec; green after the fix.

**Prevention**: Any behavior stated in `docs/`, a spec, or a code comment (deduplicate, skip, replace, never twice) MUST have a test whose input is the exact state that triggers it, not only the plain state around it. A test of a regex that strips, splits, or matches text MUST assert the full output string for each boundary: the empty or missing separator, one versus many repetitions, whitespace-only lines, a match away from the anchor, and no trailing newline. An assertion that a match "happened" does not count, because mutants of the pattern pass it. A test of a rule that decides by comparing local state with cloud state (push only what is missing, never overwrite a newer copy) MUST seed both sides, with at least one item present on both sides, one present only locally, and one newer on each side, and MUST assert the exact keys written to the other side and the values it holds afterwards, because a fixture that seeds only the local side never reaches the "present" branch. A test of a key that `docs/` calls local-only MUST seed that key in the local area, run every path that copies local keys to sync (`initialize()` default fill and migration push, `resolveSyncConflict()` write-back), and assert the key is absent from the sync area afterwards, with a control that an ordinary key is still copied. A test of an import or validation rule that `docs/` states with a type or a cap (an object and not an array, at most 200 records) MUST feed the handler one wrong-type value per branch its type guard rejects, one record above the cap and exactly the cap, and MUST assert the rejection message and that storage is unchanged; a handler no test drives counts as untested. A test of a documented send rule (what the page sends, or that it sends nothing) MUST drive the real Enter keydown and send-button click through the real handlers and assert what the page sends, whether the event was prevented and the textarea value afterwards, with the stale or special input also present with and without an attachment; a test that asserts only the return value of a helper such as `injectPrefix()` does not count. The composer fixture MUST copy the live button state (enabled for any non-empty text, with or without an attachment card) and the live attachment-card placement from a captured DOM, and MUST NOT model the button as disabled for a non-empty composer.

**Check**: For each documented behavior the change touches, find the test whose input already contains the triggering state and confirm it exists; when none exists, write it and confirm it is red on the pre-fix code. For each regex under test, list its anchors, optional groups, and repetition operators, and confirm one exact-output case per element. Run Stryker on the file and confirm no regex mutant survives. For a local-versus-cloud push or merge rule, list the collections the code reads on each side (index, per-item keys, settings keys) and confirm the fixture seeds each of them on both sides, including a non-empty item index; then run the test against the pre-fix code with a spy on the write call and confirm it lists the extra keys written. For each key a document labels local-only, confirm a test seeds it locally and reads the sync area after each copy path; when a shared fixture helper such as `populateDefaults()` omits the key, extend the helper or seed it in the test. For each import or validation rule a document states, grep `test/` for the handler and confirm one test per rejected input class plus the boundary value that is still accepted. For each documented send rule, confirm one test fires the real event at the real handler and reads what the page received; then compare the fixture's button state and attachment-card placement with a live capture and confirm the same input gives the same enabled or disabled state in both.
