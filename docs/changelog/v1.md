# v1.x 版本變更記錄

> 📂 [DS studio 文件](../) › [版本記錄](../CHANGELOG.md) › v1.x

## [1.10.1] - 2026-05-23

### 修正
- **引用回覆** (`content/quote-reply.js`)：多行文字選取時，浮動按鈕改以 `getClientRects()` 所有行矩形的聯集邊界框定位，而非僅取第一行。垂直翻轉與水平置中皆以完整選取區塊為準。

### 變更
- **`manifest.json`**：版本升至 1.10.1。

## [1.10.0] - 2026-05-22

### 新增
- **引用回覆** (`content/quote-reply.js`)：新增浮動按鈕功能，使用者在 `div.ds-virtual-list-visible-items`（AI 回覆區）內選取文字時出現。點擊「引用回覆」按鈕會將選取文字以 Markdown 引用區塊（`> line1\n> line2`）附加到目前 `<textarea>` 的內容之後。完整支援多行選取，每一行各自加上前綴。按鈕消失的條件包括：點擊按鈕、清除選取、將選取範圍捲出可視區域、視窗縮放（重新定位或隱藏），以及點擊按鈕以外的地方。
- **引用回覆單元測試** (`test/unit/content-script.quote-reply.spec.js`)：40 個 Vitest 測試，涵蓋 `isSelectionInScope`、`formatQuote`、`computeButtonPosition`、`injectQuote`、`handleSelectionChange` 與 `hideButton`，全數通過。
- **引用回覆整合測試** (`test/integration/quote-reply.spec.js`)：6 個 Playwright 測試，涵蓋按鈕出現、單行注入、多行注入、附加到既有內容、捲動隱藏與點擊外部隱藏。
- **引用回覆測試 fixture** (`test/fixtures/quote-reply.html`)：最精簡的 HTML fixture，包含帶範例內容的 `div.ds-virtual-list-visible-items` 與一個 `<textarea>`，供整合測試使用。

### 變更
- **`manifest.json`**：版本升至 1.10.0。將 `"content/quote-reply.js"` 加入 `content_scripts[0].js` 陣列（於 `content-script.js` 之後載入）。

## [1.9.0] - 2026-05-20

### 新增
- **自訂下拉組合框元件** (`popup/custom-select.js`)：以具完整無障礙支援的 `#presetSelect` 組合框（`role="combobox"` + `aria-*` 屬性）取代原本單純的 `#presetList` div 清單。支援帶防抖動的搜尋篩選、以指標事件實作的拖放排序（拖曳把手、半透明拖曳影像、插入線），以及每個項目列內的行內編輯／刪除按鈕。提供 `createPresetCustomSelect()` 工廠函式，回傳 `customSelect` API（`getSelected()`、`setSelected()`、`refresh()`、`destroy()`）。
- **工具函式匯出** (`popup/popup-utils.js`)：新增 `fuzzyMatch()`（不分大小寫的子字串／字元順序比對），以及 `debounce()`（支援 `leading`／`trailing` 選項，並正確轉送 `this` 與參數）。
- **單元測試**：13 個測試涵蓋 `fuzzyMatch`／`debounce` 工具函式；21 個測試涵蓋 `createPresetCustomSelect`，包括初始化、選取、重新整理、鍵盤導覽、搜尋篩選、拖曳排序與銷毀。
- **對話框單元測試** (`test/unit/popup-modal.spec.js`)：7 個測試，涵蓋 `prompt`／`confirm` 按鈕清理、Escape 鍵關閉、`dismissActive()` 行為，以及對話框與自訂下拉選單的整合。
- **`StorageManager` 配額備援測試** (`test/unit/storage-manager.quota.spec.js`)：7 個測試，驗證同步配額錯誤時能優雅退回本機儲存並復原。
- **`initColumnLayout` 防禦性測試** (`test/unit/popup.spec.js`)：7 個測試，驗證所有 DOM 元素缺失情境下的空值防護行為。
- **`InMemoryStorageMock` 強化** (`test/fixtures/chrome-storage-mock.js`)：加入正確的配額錯誤模擬，`setQuotaError(true)` 現在會讓 `set()` 設定 `chrome.runtime.lastError` 並跳過資料寫入，與真實 Chrome 行為一致。

### 變更
- **popup DOM** (`popup/popup.html`)：以 `#presetSelect` 取代 `#presetList`（單純 div），內含組合框觸發器、下拉面板、搜尋輸入框，以及一個不可刪除的空白選項元素。
- **popup CSS** (`popup/popup.css`)：移除所有舊的 `.preset-item*` class（`.preset-item`、`.preset-item-label`、`.preset-item-actions`、`.preset-list-footer`、`.preset-item-dragging` 等），改用 `.ds-select*` 樣式家族（`.ds-select-trigger`、`.ds-select-panel`、`.ds-select-item`、`.ds-select-search`、`.ds-select-drag-handle`、`.ds-select-ghost`、`.ds-select-insertion-line`、`.ds-select-item-actions`）。
- **popup 邏輯** (`popup/popup.js`)：移除舊的 `renderPresetList()`、`bindDragEvents()` 與所有 HTML5 拖放事件處理器（`dragstart`、`dragover`、`drop`、`dragend`）。改接 `customSelect` API 處理提示詞組的渲染、選取、排序與行內操作。新增啟動時清理過期綁定，提升穩健性。
- **`manifest.json`**：版本升至 1.9.0。
- **整合測試**：所有 Playwright 選擇器改為對應新的組合框 DOM 結構。所有 功能 spec 共 71 個測試通過。

### 修正
- **content scriptoverlay 初始化** (`content/content-script.js`)：修正 `PresetOverlay.start()` 的執行順序，確保只在 overlay `<select>` DOM 元素已存在於文件中之後才呼叫 `updateActiveId()`。
- **跨分頁 overlay 狀態汙染**：content script 中的 `chrome.storage.onChanged` 監聽器改由分頁自身的隔離狀態（`currentChatUuid`、`chatPresetMap` 與 `pendingPresetId`）推導 overlay 的選取 ID，而非直接套用儲存區中的全域 `activePresetId`。
- **popup 啟動時清理過期綁定**：`popup.js` 啟動時會清除 `chatPresetMap` 中所指提示詞組已不存在的項目，避免孤立綁定在重新載入後持續殘留。
- **`StorageManager` 同步配額備援** (`utils/storage-manager.js`)：`savePromptPresets()` 改用 `_set()` 寫入 `PRESET_INDEX`，確保 `chrome.storage.sync` 超過 `MAX_WRITE_OPERATIONS_PER_MINUTE` 時能優雅退回本機儲存。新增空值安全的錯誤訊息擷取（`syncError?.message ?? 'Unknown error'`）。
- **對話框按鈕重複** (`popup/popup.js`)：在 `Modal.prompt()` 與 `Modal.confirm()` 建立按鈕前加入 `this.actionsEl.innerHTML = ''`，避免重入呼叫時累積殘留按鈕。新增 `Modal.dismissActive()`，在從下拉選單選取提示詞組時以程式關閉對話框。
- **輸入處理器中未處理的 promise 拒絕** (`popup/popup.js`)：以 try/catch 包住 `promptInput` 與 `globalDefaultPromptInput` 的非同步 `input` 事件監聽器；儲存錯誤現在只記錄警告，不再成為未捕捉的拒絕。
- **`initColumnLayout` 空值安全** (`popup/popup.js`)：新增 5 個防禦性檢查子句（`.container`、`.column`、`.card--header`、`.card--flex`、textarea 元素）並提前返回，避免 DOM 元素缺失時因 `TypeError` 崩潰。

## [1.8.2] - 2026-05-15

### 修正
- **擴充功能 context 失效時的優雅處理**：在 `StorageManager` 中為 `chrome.storage` 的 `get`／`set`／`remove` 加上安全包裝，重新載入或更新擴充功能時不再拋出未捕捉的錯誤（例如 content scriptcontext 被拆除時的同步例外）。content script 現在會防護 `chrome.storage.onChanged`、以 `_safeGet` 讀取對話提示詞組對應表，並在 `initSettings()` 期間抑制預期中的 `Extension context invalidated` 失敗所產生的雜訊日誌。

## [1.8.1] - 2026-05-15

### 修正
- **已綁定對話的 overlay 選取狀態**：標題列的浮動提示詞組 `<select>` 在已知對話 UUID 時，改為反映 `chatPresetMap` 中該對話的綁定，而非一律顯示儲存區中的全域 `activePresetId`。如此切換對話後，overlay 能與目前對話實際使用的提示詞組保持一致。

## [1.8.0] - 2026-05-14

### 新增
- **頁面內提示詞組選擇 overlay**：DeepSeek 頁面的對話標題列（`div._2be88ba`）中央現在會出現一個浮動的 `<select>` 下拉選單，讓使用者不必開啟 popup 即可切換提示詞組。overlay 以絕對定位置於標題列內，採深色半透明樣式。
- **與 popup 雙向同步**：透過 overlay 做的變更會立即反映到 popup（反之亦然）。overlay 監聽 `chrome.storage.onChanged` 以取得提示詞組清單變更與 `ACTIVE_PRESET_ID` 更新，popup 送出的 `ACTIVE_PRESET_CHANGED` 訊息則直接更新 overlay 的選取值。
- **SPA 導覽韌性**：以 `MutationObserver` 監看對話標題列是否被替換（SPA 切換對話），並自動以正確的綁定狀態重新掛載 overlay。
- **對話綁定支援**：在已綁定的對話上從 overlay 選取提示詞組，會更新 UUID 對提示詞組的綁定（`chatPresetMap`）。選取空白選項則解除該對話的綁定。

## [1.7.2] - 2026-05-14

### 修正
- **切換對話導致 UUID 對提示詞組綁定遺失**：修正切換對話時一律遺失提示詞組綁定、退回空白狀態的回歸問題。content script 中的 `handleChatChange()` 以已停用的 `promptPresets` 儲存鍵驗證綁定有效性，而該鍵已在 v1.7.0 的結構遷移中移除，導致每個綁定都被誤判為過期並刪除。現改用 `StorageManager.getSettings()`，可從新的逐鍵結構（`dsPresetIndex` + `dsPreset_<id>`）正確解析提示詞組。

## [1.7.1] - 2026-05-14

### 修正
- **編輯提示詞組內容後注入過期前綴**：修正在 popup 編輯提示詞組內容後直接送出訊息，卻注入舊內容的回歸問題。content script 中的 `chrome.storage.onChanged` 監聽器現在能正確偵測新的逐組儲存鍵（`dsPresetIndex` 與 `dsPreset_<id>`）變更，立即觸發 `updatePromptPrefixFromBinding()`，而非只對已停用的 `promptPresets` 鍵作出反應。
- **與下拉選單互動後側邊欄自動隱藏未收合**：修正滑鼠移出浮動／下拉選單（`ds-dropdown-menu ds-elevated`）且未再進入側邊欄時，不會觸發側邊欄收合的回歸問題。原因是 `onLeave` 處理器中的 `!isCollapsed()` 條件寫反，導致側邊欄已展開時無法收合。

## [1.7.0] - 2026-05-13

### 新增
- **每個提示詞組獨立儲存鍵**：重構 `StorageManager`，將每個提示詞組存放在各自唯一的鍵（`dsPreset_<id>`）下，而非單一巨大陣列。藉此繞過 Chrome 同步儲存每個項目 8KB 的上限，可容納更大、更多的提示詞組。
- **Plan A：本機權威追蹤**：實作「本機權威」機制，修正同步資料蓋過本機資料的重大問題。同步失敗時（例如超出配額），受影響的鍵會被標記為本機權威。之後讀取時，擴充功能會對這些鍵優先採用較新的本機資料，而非過期的雲端資料，確保超出同步配額時不會遺失資料。

### 變更
- **儲存結構演進**：新增 `dsPresetIndex` 維護提示詞組 ID 的排序清單，以及 `dsLocalAuth` 追蹤本機權威鍵。舊的 `promptPresets` 鍵會在首次載入時自動遷移為新格式。

## [1.6.6] - 2026-05-12

### 修正
- **新分頁繼承其他對話的提示詞**：修正在新分頁開啟新對話頁面（`https://chat.deepseek.com/`）時，會從前一個分頁的全域 `activePresetId` 繼承 `promptPrefix` 的問題。content script 不再於 `initSettings()` 中透過 `getActivePromptContent()` 預載 `promptPrefix`；`promptPrefix` 現在完全由 `handleChatChange()` 依目前對話的 UUID 綁定推導。`handleChatChange()` 的無 UUID 分支現在會無條件清除 `promptPrefix`，修正初始 `currentChatUuid` 已是 `null` 而跳過先前檢查的情況。
- **手動切換對話時意外自動綁定**：修正在新對話頁面選取提示詞組後，手動切換到另一個（先前未綁定的）既有對話時，會錯誤地將該對話自動綁定到待定提示詞組的問題。自動綁定現在需要明確的 `awaitingNewChatUuid` 旗標，該旗標只在使用者於無 UUID 頁面實際送出訊息（按 Enter 或點擊送出按鈕）時設定。旗標由 `handleChatChange()` 消耗，並在 5 秒後自動清除，避免送出失敗後殘留過期旗標。

### 變更
- **收緊自動綁定觸發條件**：`handleChatChange()` 中的自動綁定分支（先前在任何 `no-UUID → UUID` 轉換時觸發）現在要求 `awaitingNewChatUuid === true`，依 `TODO.md` 的要求確保每個對話各自維持獨立的綁定關係。

- **空白選項永遠可見**：popup 現在會無條件附加空白下拉選項，即使所有自訂提示詞組都已移除，介面仍保持一致。

### 修正
- **空提示詞組安全性**：新增安全檢查，處理提示詞組陣列可能為空的情況，避免渲染下拉選單時發生執行期錯誤。

## [1.6.2] - 2026-05-12

## [1.6.1] - 2026-05-11

### 新增
- **同步儲存衝突解決**：在 `StorageManager` 中實作穩健的衝突偵測與解決機制。初次同步時若雲端資料與本機資料不同，擴充功能會向使用者顯示「Cloud Sync Conflict」（雲端同步衝突）警告，而非靜默覆寫。
- **智慧合併提示詞組**：新增 `mergePresets` 邏輯，依 `id` 去除重複的提示詞組，並依 `updatedAt` 時間戳記保留最新內容。同步衝突解決與 JSON 匯入皆使用此邏輯。
- **強化 JSON 匯入**：「Restore Settings」（還原設定）流程改用合併邏輯處理提示詞組。介面與全域設定會被覆寫，提示詞組則智慧合併以避免資料遺失。
- **衝突處理介面**：popup 新增自訂警告對話框，在有待處理的同步衝突時出現，並提供「Merge & Sync」（合併並同步）選項。

## [1.6.0] - 2026-05-11

### 新增
- **Chrome 同步儲存（`chrome.storage.sync`）**：升級內部的 `StorageManager` 以支援雙重儲存。跨裝置設定（提示詞組、使用中的提示詞組、UUID 綁定與全域預設值）現在會自動同步到所有登入同一帳號的 Chrome。超出配額時會自動退回 `chrome.storage.local`。
- **JSON 匯出（備份）**：popup 新增「備份設定 (匯出 JSON)」按鈕，將所有提示詞組與介面設定匯出為可下載的 JSON 檔。
- **JSON 匯入（還原）**：popup 新增「還原設定 (匯入 JSON)」按鈕，從備份檔還原設定，完整覆寫目前的本機與同步資料。

## [1.5.5] - 2026-05-11

### 修正
- **新對話沿用過期的提示詞組選取**：修正先前在另一個新對話選取提示詞組後，再開啟新對話（`/`）會錯誤還原先前選取的問題。popup 現在改為查詢 content script 記憶體中的 `pendingPresetId`，不再依賴過期的 `chrome.storage.session` 意圖。每次對話狀態轉換時都會正確清除待定選取，確保回到新對話頁面時是乾淨的狀態。

## [1.5.4] - 2026-05-10

### 修正
- **重新開啟時提示詞組選取被清除**：未綁定的對話中，新增的提示詞組不再於重新開啟 popup 時被清除。若目前有 UUID，新增時會將新提示詞組綁定到該 UUID；全新對話則以每分頁的 session 儲存意圖保留選取，直到路徑改變為止。

## [1.5.3] - 2026-05-10

### 修正
- **新對話首次送出注入失敗**：修正在全新對話（無 UUID）上新增提示詞組後，第一則訊息送出時未注入的問題。content script 的綁定解析器在沒有 UUID 綁定時，現在會正確退回 `pendingPresetId`，確保新建立的提示詞組立即注入。
- **統一的 `ACTIVE_PRESET_CHANGED` 處理器**：簡化 `ACTIVE_PRESET_CHANGED` 訊息處理器，改用統一的解析器，而非直接讀取 `presetContent`，確保訊息驅動與儲存驅動的更新一致。

## [1.5.2] - 2026-05-07

### 修正
- **側邊欄下拉選單懸停區域偵測**：以更穩健的做法取代脆弱的 `event.relatedTarget`：在 `document` 上以捕獲階段監聽 `mouseover`，依 class 模式（`ds-floating*`、`ds-dropdown*`、`ds-elevated`）偵測浮動／下拉元素。使用 `requestAnimationFrame` 延後處理，避免游標從下拉選單回到側邊欄時的競爭條件；與 React portal 渲染的選單互動時，以及從下拉選單移回側邊欄時，側邊欄現在都能正確保持展開。

## [1.5.1] - 2026-05-07

### 修正
- **popup 介面間距一致性**：移除 `header` 與 `.checkbox-group` 元素多餘的 `margin-bottom`。各列之間的垂直間距現在統一由卡片的 `gap: 12px` 控制，消除重複間距造成的不一致。
- **新對話輸入框不受輸入框寬度設定影響**：在 `InputWidth` 模組中將 `.aaff8b8f` 加為獨立的 CSS 選擇器（不要求 `._871cbca` 父層）。新對話頁面的 DOM 結構不同，輸入區 class 並未巢狀於 `._871cbca` 之下，導致先前的選擇器 `._871cbca .aaff8b8f` 無法套用。
- **輸入框寬度未受對話寬度限制**：修正 `InputWidth` 中兩處直接使用 `this.percent` 而非 `this.getEffectivePercent()` 的呼叫點：`enable()` 方法與 `MutationObserver` 重新套用的回呼。有效百分比會在啟用對話寬度調整且其值較小時，正確將輸入框寬度限制在對話寬度以內。
- **跨分頁提示詞組汙染**：實作每分頁提示詞組隔離。content script 不再直接依全域 `ACTIVE_PRESET_ID` 儲存鍵更新 `promptPrefix`，改由 popup 直接向使用中分頁的 content script 傳送 `ACTIVE_PRESET_CHANGED` 訊息。每個分頁獨立追蹤自己的 `pendingPresetId`，並透過 `updatePromptPrefixFromBinding()` 依自身的 UUID 綁定推導 `promptPrefix`。首則訊息的自動綁定也改用每分頁狀態，而非全域儲存。
- **懸停下拉選單時側邊欄收合**：滑鼠從側邊欄移入浮動／下拉元素（例如透過 React portal 渲染的右鍵選單）時，側邊欄現在會保持展開，直到使用者關閉下拉選單。先前為了操作溢出的下拉選單而離開側邊欄邊界框時，會觸發收合計時器，導致無法點選下拉選單項目。修正方式是在 `document` 上以捕獲階段監聽 `mouseover`，依 class 模式（`ds-floating*`、`ds-dropdown*`、`ds-elevated`）偵測浮動元素、取消收合計時器，並監看下拉選單的 `mouseleave` 以進行清理。

### 變更
- **content script 的儲存監聽器**：以訊息式的每分頁通訊取代被動的 `ACTIVE_PRESET_ID` 監聽器。儲存區只監看 `PROMPT_PRESETS` 與 `CHAT_PRESET_MAP` 的變更；content script 會依目前對話的 UUID 綁定重新計算 `promptPrefix`。
