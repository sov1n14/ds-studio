## [4.15.0] - 2026-08-01

### Added

- **編輯視窗 `Esc` 關閉**（`popup/editor/editor.js`）：`DOMContentLoaded` 內新增 window 層級 `keydown` 監聽器，`e.key === 'Escape'` 時呼叫 `window.close()`。視窗由擴充功能經 `chrome.windows.create` 開啟，可被腳本關閉；既有 `pagehide` 監聽器在卸載前以 fire-and-forget 寫入未存內容（內容與名稱輸入框），故快捷關閉不遺失資料。不攔截事件、不影響其他按鍵。

### Tests

- `test/unit/editor.spec.js`：新增 1 測試（source assertion，錨定 `// Esc 關閉視窗` 註解）— 斷言存在 window 層級 `keydown` 監聽器、`e.key === 'Escape'` 檢查與 `window.close()` 呼叫（45 測試全綠，由 `test-executor` 認證，exit code 0）。

### Documentation

- `docs/architecture/POPUP.md`：自動儲存段落補上 `Esc` 關閉行為。
- `docs/spec/01-prompt-system.md`：編輯視窗段落標註 v4.15.0 並補上 `Esc` 關閉說明。
- `docs/FEATURES.md`、`docs/en/FEATURES.md`：操作步驟補上 `Esc` 關閉快捷鍵。

### Version

- **`manifest.json`**: Bumped `4.14.0` → `4.15.0`（minor — 新增使用者可見功能）。

## [4.13.0] - 2026-08-01

新增「連網搜索」三態設定：可指定 DeepSeek 頁面智能搜索按鈕的保持狀態（開啟 / 關閉），或完全不干擾（預設）。

### Added

- **彈出選單「UI 調整」卡片新增「連網搜索 / Web Search」單選群組**（`input[name="websearchToggle"]`，三選項 `預設` / `開啟` / `關閉`），儲存鍵 `dsWebSearchToggle`（字串，預設 `'default'`，隨 sync 同步）。選項沿用既有 `.locale-option` 樣式，不引入新元件。
- **內容腳本 `content/websearch-toggle.js`（新檔，仿 `hide-thinking.js` 的模組形狀）**：`開啟` 使頁面智能搜索按鈕保持 `aria-pressed="true"`，`關閉` 保持 `"false"`，`預設` 完全不動作。**核心規則：只在狀態不符時點擊** —— 相符時點擊反而會把狀態切換走；每次點擊受 `CLICK_COOLDOWN_MS`（500ms）節流，避免我們自己點擊觸發的 mutation 造成點擊 ping-pong（常數暴露供測試歸零）。
  - **元素辨識（使用者實測回報後修正）**：實頁有**兩個外觀相同**的 `.ds-toggle-button[aria-pressed]` 元素（深度思考與智能搜索），`querySelector` 固定取到第一個（錯的）。樣本檔 `to-do/samples/websearch.html` 僅含一個元素，未反映實頁。修正為以 **label 文字含「搜索」** 者為準（`_pickByLabel()`），不受元素順序影響，並保留既有第一個匹配與通用 `[aria-pressed]` 選擇器作為備援。
  - **SPA 韌性**：單一 `MutationObserver` 雙目標 —— body `childList + subtree`（SPA 重渲染的節點替換）與按鈕本身的 `attributes, attributeFilter: ['aria-pressed']`（使用者手動點擊／頁面邏輯的原地翻轉，childList-only 會漏）；callback 內重新 arm，使 attribute 目標永遠指向存活元素。
  - **主開關感知**：僅當主開關 `isEnabled` 為真且模式非 `default` 時才動作。`chrome.storage.onChanged`（僅 `local` 命名空間）同時監控 `isEnabled` 與 `dsWebSearchToggle`，支援免重整即時切換；模式在 `on`/`off` 間互換時直接重新套用，不需 disable。`disable()` 不還原按鈕狀態（按鈕非本擴充所屬，停止強制即放開）。

## [4.12.0] - 2026-08-01

新增「防止自動回滾」開關：原本僅在「回到頂部」與 Markdown 匯出期間短暫生效的防回滾保護，可由使用者設為常駐。

### Added

- **彈出選單「UI 調整」卡片新增「防止自動回滾 / Prevent Auto-Scroll」核取方塊**（`#preventAutoScrollToggle`），儲存鍵 `dsPreventAutoScroll`（布林值，預設 `false`，隨 sync 同步）。開啟後 `PreventAutoScroll` 全時抑制頁面的向下自動捲動，不再只在「回到頂部」與 Markdown 匯出的操作視窗內生效。
- **常駐模式實作在共用節流點，兩個既有呼叫端零改動。** `content/prevent-auto-scroll-bridge.js` 新增 `setPersistent()` / `isPersistent()` / `start()`，常駐狀態與既有的 `enabled` 旗標並存於同一個隱藏 bridge 元素的 `dataset` 上（不引入模組層可變狀態）。`harvest.js:382-384` 與 `go-top.scroll.js:82-92` 均未修改。
  - **`disable()` 改為在常駐模式下 no-op。** 這是本次唯一動到既有函式的一行守衛，也是必要的：該旗標**沒有引用計數**，而 `harvest.js` 在 `finally` 中**無條件**呼叫 `disable()`。若不加守衛，使用者開啟常駐後只要匯出一次 Markdown，保護就會在匯出結束時被靜默關掉。`setPersistent(false)` 刻意繞過此守衛直接寫入 `dataset`，否則關閉常駐將永遠無法解除保護。
  - **主開關感知**：僅當主開關 `isEnabled` 為真且 `dsPreventAutoScroll` 為真時才常駐。`start()` 沿用 `content/hide-thinking.js` 的啟動慣例（初次讀取 → 套用 → 註冊 `chrome.storage.onChanged`，忽略非 `local` 命名空間），支援免重整即時切換。兩個鍵的任一變更都會重新自儲存空間讀取後重算，不快取部分狀態。
- **已知取捨（使用者已確認接受）**：既有的 MAIN-world 補丁是 `Element.prototype` 層級的全域攔截，只擋**向下**捲動且**無法區分**程式觸發與使用者觸發。因此常駐開啟時，DeepSeek 串流回覆的「自動跟隨捲到最新」也會一併被擋，需自行向下捲動；原生滾輪／觸控板捲動不經這些 JS API，不受影響。預設關閉即為此取捨的緩衝。

### Fixed

- **⚠️ 使用者可見：拖曳調整提示詞組順序後，下次開啟彈出選單順序又跳回舊的。** `mergePresets()`（`utils/storage-manager.presets.js:187-192`）原本只在時間戳**嚴格較新**時才採用對應側的 `order` 陣列；兩側相等時 `chosen` 保持 `undefined`，退回合併 `Map` 的插入順序。而該插入順序是「本機已快取的提示詞組在前、其餘依雲端順序在後」，因此結果順序由**哪些提示詞組物件剛好存在於 `chrome.storage.local`** 決定，而非由已儲存的順序陣列決定 —— 任何本機已快取的組都會浮到最前面。
  - **平手是常態，不是邊界狀況。** 單次 `_set()` 先寫入 `chrome.storage.sync`（`utils/storage-manager.js:332`），再把**同一個物件**鏡射到 `chrome.storage.local`（`:358`）。`orderUpdatedAt` 隨物件一起寫入兩區，因此任何一次成功儲存後兩側必然逐位元相同。已對照使用者實機 dump 確認：兩側同為 `orderUpdatedAt: 1785070411839`。
  - **修法**：平手時採用雲端側的 `order`。實際條件收斂為「僅當 `baseTs > incTs` 時採用本機順序，其餘一律採用雲端」。
  - **為何選雲端而非本機**：平手代表無從判斷新舊，而雲端勝出是**自我收斂**的 —— 各裝置最終落在同一個陣列。本機勝出會讓兩台裝置各自永久保留自己的順序，因為讀取路徑從不把合併決定寫回雲端（`_get()` 只寫回 `local`，見 `utils/storage-manager.js:284-290`，且該寫回只在雲端勝出時觸發）。保護「本機確實較新」的職責屬於 `dsLocalAuth` 重推佇列，不屬於平手規則。
  - **自我延續的迴圈**：此缺陷會自我維持。`resolveSyncConflict()` 以 `Math.max(localTs, syncTs, Date.now())` 重蓋時間戳（`utils/storage-manager.sync.js:96-100`），單一 `mergedMeta` 寫進兩個儲存區，於是時間戳立刻再次平手，下次開啟又走同一條退回路徑。

## [4.11.18] - 2026-07-26

修復跨裝置同步：提示詞組排序回滾、以及在一台裝置刪除的組於另一台復活。兩者是同一個缺陷的兩個受害者。

### Fixed

- **⚠️ 使用者可見：在 A 機拖曳調整提示詞組順序，同步過去後下次開啟又跳回舊順序；在 A 機刪除的提示詞組，會在 B 機重新出現。** 根因在 `retrySync()` 的待推送迴圈（`utils/storage-manager.sync.js:199-240`）。該迴圈走訪 `dsLocalAuth` 記錄的「上次寫入雲端失敗」鍵，把本機值推上雲端。它對 `PRESET_INDEX` 與 `dsPreset_*` 內容鍵都有「先比新舊再推」的守衛，但 **`PRESET_ORDER_META` 與 `PRESET_TOMBSTONES` 兩者都沒有**，`shouldPush` 停在預設值 `true`，落入無條件推送 —— 陳舊的本機值盲目蓋掉雲端較新的值。
  - **為何漏掉 `dsPresetOrderMeta`**：既有守衛的條件是 `key.startsWith('dsPreset_')`，**帶結尾底線**。`'dsPresetOrderMeta'` 第 8 個字元是 `O` 而非 `_`，`startsWith` 為偽，因此它既不匹配 `PRESET_INDEX` 分支也不匹配 `dsPreset_*` 分支。這是一個字串前綴的近似碰撞，肉眼閱讀極易誤判為已被涵蓋。
  - **墓碑的語意與其他鍵不同，不是「較新者整份勝出」**。墓碑是以提示詞組 id 為鍵的物件 `{ [id]: { ts, deleted } }`。兩台裝置可以各自在離線期間刪除**不同**的組；以本機整份取代雲端會靜默復活對方刪除的那一組。修法為**逐 id 聯集**：單邊才有的 id 保留，兩邊都有的 id 取 `ts` 較新者，且空的本機集合不得清空雲端集合。

  - **本次刻意未處理**：`dsPresetOrderMeta` 內另存了一份順序陣列副本 `.order`，與 `dsPresetIndex` 構成重複真相，兩者由 `savePromptPresets()` 的兩次獨立 `_set()` 寫入（`utils/storage-manager.presets.js:233`、`:236`）而可獨立失敗脫鉤。移除 `.order` 屬結構整理而非修 bug，已刻意延後至實機驗證本次修復有效之後，以免兩個變因混在一起難以定位。

## [4.9.0] - 2026-07-11

### Changed

- **Two-layer temporary-conversation deletion architecture**: Real-time deletion and crash/shutdown remediation are now fully separated.
  - **Layer 1 (real-time, content script)**: `beforeunload` (tab/browser close) now calls `fetch(..., { keepalive: true })` directly instead of relaying through the Service Worker via `chrome.runtime.sendMessage` — removing the unreliable IPC hop that could fail to arrive during tab teardown. An entry is removed from the pending-delete queue only after the delete API confirms success.
  - **Layer 2 (remediation, Service Worker, `onStartup`-only)**: The existing `chrome.runtime.onStartup` listener (previously used only for cloud-preset sync) is extended with pending-delete remediation — on every browser restart, it reads the shared queue and retries each entry with this device's own locally-cached auth token, removing an entry only on confirmed success and incrementing `attemptCount` otherwise.
- **Cross-device pending-delete queue as single source of truth**: The pending-delete queue moved to `chrome.storage.sync` (`dss-pending-deletes-sync`, `{ chatUuid, attemptCount }`) with no separate local-only copy — any device signed into the same Chrome account can remediate any queue entry using its own locally-captured auth token, whether or not it originally tracked that conversation.
- **Sync-Change Safeguard**: A `chrome.storage.onChanged` (sync area) listener triggers an additional remediation sweep to mitigate the `onStartup` cold-start hydration race, guarded by a new device-local open-set (`dss-open-temp-uuids`, local-only) so the currently-open conversation on this device is never deleted by the sweep.

### Privacy

- `authToken` is cached only in `chrome.storage.local` (`dss-last-auth-token`) and never syncs to any other device. Only the non-sensitive `chatUuid` and `attemptCount` are written to `chrome.storage.sync`.

## [4.8.2] - 2026-07-11

### Fixed

- **8KB payload-size guard in front of the `dsLocalAuth` retry queue** (report.md §4.2/§6 Step 6, final step of the sync-refactor plan): `_set(items)` in `utils/storage-manager.js` now splits every write batch per-key by serialized UTF-8 byte size before attempting `chrome.storage.sync.set()`. Keys whose `{ [key]: value }` payload exceeds `QUOTA_BYTES_PER_ITEM` (8192 bytes) are diverted before the sync call ever fires: written to `chrome.storage.local` only (value never lost), tracked in a new local-only `dsOversizedKeys` list, and explicitly excluded from `dsLocalAuth`. - **Self-healing tracking**: a key already in `dsOversizedKeys` is automatically removed the next time it's written at a size at or under the 8192-byte limit.
- **`hasOversizedItems()`** (new, `utils/storage-manager.sync.js`): returns `true` iff `dsOversizedKeys` is non-empty.

## [4.0.0] - 2026-06-13

### Changed

- **Large-file modularization refactor** (`to-do/to-implement/requirement.md`): Five oversized source files and one stylesheet were split into smaller, single-concern modules to comply with the `coding-guidelines` file-size thresholds (JS 450 proactive / 600 absolute; CSS 350 / 500). Runtime behavior and every public API are **unchanged** — the split is purely structural. All 985 unit tests across 49 files remain green; no test assertions were modified.

- **Dual-load split pattern**: Each oversized singleton keeps its original filename as a state-bearing **entry file**; cohesive method groups move into **bundle files**. Bundle files attach their method group to a `globalThis.__DS_*` key (guarded by `if (typeof module !== 'undefined' && module.exports)` for Vitest); the entry file runs `Object.assign(Singleton, globalThis.__DS_* )` to merge them before attaching to `window` / `module.exports`. `content-script` and `popup` helpers that close over mutable state use a `createX(ctx)` factory with live getter/setter callbacks so cross-file state stays in sync. No ES `import`/`export` is introduced; classic-script (production) and Vitest (test) load paths are both preserved.

- **`utils/storage-manager.js` split** (1199 → 546 lines entry):
  - `storage-manager.js` (546) — entry: `KEYS`/`DEFAULTS`/`errors`, safe wrappers, `getSettings`, `initialize`, shared state
  - `storage-manager.chunking.js` (77) — ChatPresetMap physical chunking & reconciliation
  - `storage-manager.lock.js` (132) — cross-context advisory lock (Method C)
  - `storage-manager.sync.js` (206) — cloud sync, conflict resolution, restore
  - `storage-manager.presets.js` (537) — preset CRUD, merge, chat-binding
  - Shared private state (`_chunkIndexCache`, `_metaCache`, `_chatPresetMapChainTail`, `_enqueueChatPresetMapWrite`, `_buildNextMeta`) was hoisted onto the `StorageManager` object so merged bundle methods access it via `this`.

- **`content/go-top.js` split** (1040 → 439 lines entry):
  - `go-top.js` (439) — entry: state, observers/listeners, route handling, lifecycle, overlay helpers
  - `go-top.locate.js` (264) — DOM query/locator/visibility helpers
  - `go-top.render.js` (354) — button render/SVG, injection strategies, wrapper observer, mode transitions
  - `go-top.scroll.js` (173) — `scrollToTopAndWait` animation engine

- **`content/censor-reply-restore.js` split** (1006 → 426 lines entry):
  - `censor-reply-restore.js` (426) — entry: state, XHR/SSE hook, parser, MutationObserver, detection, lifecycle
  - `censor-reply-restore.markdown.js` (198) — Markdown → HTML renderer
  - `censor-reply-restore.dom.js` (489) — fragment extraction, DOM injection, think-block construction
  - `censor-reply-restore.storage.js` (86) — restored-message persistence & session keys

- **`content/content-script.js` split** (825 → 474 lines entry):
  - `content-script.js` (474) — entry: state, init, navigation, prefix injection, input interception, exports
  - `content-script.export.js` (346) — Markdown export pipeline (`parseHtmlToMarkdown`, `convertMessageNodeToMarkdown`, `exportConversationToMarkdown`, `downloadMarkdown`, `formatSystemTime`)
  - `content-script.overlay.js` (193) — `PresetOverlay` via `createPresetOverlay(ctx)` factory with live state getters/setters

- **`popup/popup.js` split** (831 → 536 lines entry):
  - `popup.js` (536) — entry: DOMContentLoaded bootstrap, state, inline event-handler wiring, `updateEditPresetBtnState`, `openEditorWindow`, `refreshSyncStatus`
  - `popup.modal.js` (196) — `Modal` + `Toast` UI components
  - `popup.preset-manager.js` (132) — preset CRUD helpers via `createPresetManager(ctx)`
  - `popup.backup-manager.js` (207) — backup/restore & force-sync handlers via `createBackupManager(ctx)`

- **`popup/popup.css` split** (388 → 191 lines):
  - `popup.css` (191) — `:root` variables, dark-mode, layout grid, typography/cards/inputs base
  - `popup-controls.css` (261) — switch toggle, buttons, icon buttons, range slider, toast (loaded after `popup.css` so it inherits the `:root` variables)

### Changed (load order)

- **`manifest.json`** `content_scripts[0].js`: inserted the new bundle/collaborator files immediately before their entry files (storage bundles → `storage-manager.js`; censor bundles → `censor-reply-restore.js`; `content-script.export.js` + `content-script.overlay.js` → `content-script.js`; `go-top.locate.js` + `go-top.render.js` + `go-top.scroll.js` → `go-top.js`).
- **`popup/popup.html`**: added the four storage-manager bundles before `storage-manager.js`; added `popup.modal.js` / `popup.preset-manager.js` / `popup.backup-manager.js` before `popup.js`; added the `popup-controls.css` `<link>` after `popup.css`.
- **`popup/editor/editor.html`**: added the four storage-manager bundles before `storage-manager.js`.

### Changed (tests)

- **`test/setup/vitest.setup.js`**: added side-effect preload imports of all bundle/collaborator files in dependency order, so that when specs import an entry file the `globalThis.__DS_*` keys are already populated and `Object.assign` produces the fully-assembled singleton. This kept ~16 ES-`import` specs working with zero per-spec changes.
- **`test/unit/popup-modal.spec.js`** and **`test/unit/popup-custom-select.spec.js`**: updated their `readFileSync` path from `popup/popup.js` to `popup/popup.modal.js` (the `Modal` object literal moved there, with its `const Modal = {` … `};` shape preserved verbatim so the existing extraction regex still matches).
- Full suite: 985 tests across 49 files, all passing — identical to the pre-refactor baseline.

- **Manifest**: Version bumped to 4.0.0 (major — significant architectural restructure).
